# worktree 隔离

只在几个互不依赖的任务确实要同时改同一批文件时读。

- `isolation: "worktree"`（可选，写在任务上，或写在计划顶层作为默认）：少用，做法同 Claude Workflow 的 `isolation: 'worktree'`，只在几个互不依赖的任务确实要同时改同一批文件时用；能按文件划分就划分，让排队处理重叠，要接力的任务按顺序跑、不隔离。每个隔离任务多占一份检出的磁盘，随仓库大小变（8.5k 文件的仓库约 1 秒、240MB），同时最多 `CODEX_FLOW_MAX_WORKTREES`（默认 4）个，只支持 git 仓库、不支持已初始化子模块。写在计划顶层时，单个任务写 `"isolation": false` 不隔离。任务名只差标点、空白或大小写时目录会重名，拒绝启动。
  - 运行：在 `$CODEX_FLOW_HOME/worktrees/<runId>/<任务名>` 物化主工作区此刻的内容（含未提交和未跟踪的文件），worktree 的 index 是 HEAD：任务里 `git diff` 看到的改动内容和主工作区相同，但主工作区已暂存的改动显示为未暂存、已暂存的新文件显示为未跟踪；被忽略的条目只有 node_modules、.venv、venv 用符号链接指回主工作区（任务在里面装依赖会写进主环境，会改依赖的任务不要隔离），项目根 `.worktreeinclude`（写法同 Claude Code）列出的被忽略文件复制进来，其余不带；环境里的本地包指向主工作区时汇总告警，验收可能测的不是隔离里的代码。验收在 worktree 里跑。
  - 成果：不合回主工作区。有改动就存成分支 `codex-flow/<runId>/<任务名>`（父提交是开始时的主工作区：干净时就是 HEAD，有未提交内容时是一个包含它们的提交），没有改动就什么都不留；被忽略目录（如 `build/`）里的产物不在分支上。越界写入和环境链接被换掉只在汇总提示，状态按执行和验收定。worktree 目录随即删除，写 `"keepWorktree": true` 保留。排在隔离任务后面的任务看不到它的改动，开始时 stderr 提示。
  - flow 结束后由我合并：读汇总里的「成果在分支 …」，先用给出的「查看」命令看 diff，确认后运行「合进主工作区」命令（`git diff --binary <基准> <分支> | git apply`，只改工作区、不提交）；几个分支改了同一处时 `git apply` 会失败，由我手动合并。合完或决定不要后，`codex-flow.mjs clean <runId>` 删掉仍停在成果上的分支（之后有新提交的不删）和残留 worktree；不清理时含成果分支的运行保留 30 天，到期后下一次运行时删除。
  - 重做：`run --resume <runId> --rerun <任务名>` 从最新的主工作区重做，上次的分支还停在成果上就换成新的；有人在上面提交过就不动它，任务启动失败。只改了 `checks` 的续跑按存下的成果重建 worktree 验收，并按这次的 `writes` 重查越界。
  - 续跑时发现旧 worktree：保留原目录，新建的目录加唯一后缀，避免覆盖崩溃或归档失败时留下的唯一改动；只重跑验收也一样。旧目录记进 `state.leftovers.worktrees`，汇总列出路径，先到该目录查看、取回改动。任务被删除、改名或取消隔离时，旧目录也继续登记，随隔离成果保留 30 天，到期清理或手动 `clean` 会删除目录及 git worktree 登记。执行器进程仍在收尾时不能续跑或 `clean`。
