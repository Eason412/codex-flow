# 审查与排查修复的任务要点

派审查或修 bug 的任务时，把下面对应的一段写进任务说明，再补上具体的目标、输入、`writes` 和 `checks`。项目自己的约定由 Codex 从项目 `AGENTS.md` 和项目 Skill 读取，这里不写。安全漏洞扫描不走这里。

## 审查（只读，`-j review`）

找功能 bug，重点看：

- 边界输入：空值、空集合、极大极小值、重复项、格式不合法的输入。
- 状态与先后：调用顺序变了、中途取消或重试、并发或异步回调交错时，状态是否还对。
- 错误处理：异常被吞掉、出错时返回空结果或默认值而不报错、错误信息丢了原因。
- 计算细节：下标差一、单位或坐标系混用、取整与精度。
- 接口一致：调用方和被调用方、前端和后端、写入方和读取方对字段名、类型、可空性的理解是否一致。

每条问题写清触发条件（什么输入或操作会出错）和代码依据（文件与行）；说不出怎么触发的不报。命名、风格和可维护性默认不报，除非任务另有要求。只分析，不修改文件。

## 排查修复（`-j report`）

1. 复现：先写一个能稳定复现问题的失败测试；复现不出来就停下，在 `report` 里写清试了什么，不凭猜测改代码。
2. 定位：缩小到具体的函数和条件，找到根因。
3. 修复：改根因，不只压住症状；同一根因在别处也出现时一并说明。
4. 验收：用第 1 步的测试和任务给的 `checks` 确认通过。

如果发现是测试或预期本身写错了，不改代码迁就，在 `report` 的偏离里说明。
